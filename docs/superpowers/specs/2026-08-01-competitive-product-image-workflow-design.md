# 1688 竞品分析与商品图片工作流系统设计

- 日期：2026-08-01
- 状态：设计已确认，等待文档复核
- 目标版本：第一版

## 1. 概述

本系统是一个单用户、本机运行、通过浏览器访问的商品视觉工作台。它面向 1688 运营人员，首批覆盖热熔胶棒、热熔胶枪等工业品类目。

系统把分散的图片工作组织为一条可追溯工作流：

1. 建立并复用商品资料；
2. 手动上传竞品图片；
3. 生成逐图分析与跨图片综合报告；
4. 人工纠正模型分析；
5. 生成并选择设计方向；
6. 编辑主图和详情页图片清单；
7. 批量生成图片；
8. 对单图进行圈选式 AI 微调；
9. 管理版本并导出 PNG/JPG。

第一版以成图质量和主观可用性为最高优先级，不设自动质量合格分数。

## 2. 目标与非目标

### 2.1 目标

- 让 1688 运营人员无需设计师协助即可完成从竞品研究到成图导出的闭环。
- 同时支持商品主图套图和商品详情页，并允许一次任务选择其中一种或两种。
- 保存商品、竞品研究、设计方案、生成结果和微调版本，支持长期复用与追溯。
- 支持百炼、火山方舟/豆包和 GPT 中转，并按工作流场景配置不同模型。
- 允许模型调用失败后单项重试，不因一张图失败而重做整批。

### 2.2 非目标

- 不做账号、登录、角色、权限、组织或多人审批。
- 不自动抓取 1688 链接，不自动搜索竞品。
- 不做云端或局域网服务，不制作 Electron/Tauri 桌面客户端。
- 不做 Photoshop 式画布、文本图层、矢量元素或拖拽排版编辑器。
- 不导出 PSD、SVG 或可编辑工程文件。
- 不承诺生成商品与参考图完全一致；允许端到端模型造成细微外观变化。
- 不自动发布商品或图片到 1688。
- 不依据点击率、询盘率等线上经营指标自动判断图片优劣。

## 3. 用户与运行边界

系统只有一个操作者。该用户可以访问全部商品、设置、任务和文件，不存在权限差异。

本地服务只监听 `127.0.0.1`，浏览器通过本机地址访问。第一版通过一个启动命令同时启动前后端；不要求按操作系统制作安装包。关闭浏览器不影响已经提交的后台任务；关闭本地服务会中断正在执行的外部模型调用。

业务数据、上传图片、生成结果和导出文件保存在本机。模型请求会把相关输入发送给用户配置的外部 API。

## 4. 核心用户流程

### 4.1 商品建档

用户在商品库创建商品并维护“商品资料包”：

- 商品名称；
- 一张或多张商品参考图；
- 规格参数；
- 核心卖点；
- 可选备注。

提交 AI 任务前，后端检查该任务所需资料是否存在。规格和卖点是可信业务输入，模型不得凭空补写未提供的参数。

### 4.2 竞品研究

1. 用户在商品下手动上传竞品图片。
2. 系统逐图分析版式、配色、信息层级、文案、卖点、场景和视觉手法。
3. 用户可以修改逐图分析卡片；人工值与模型原始值分别保存。
4. 系统基于当前卡片生成综合报告，内容包含：
   - 跨图片的行业共性规律；
   - 有证据图片引用的主要结论；
   - 竞品未充分覆盖且自有商品资料能够支持的差异化机会；
   - 面向后续成图的设计建议。
5. 补充或删除竞品素材、修改分析卡片后，系统创建新的分析版本，不覆盖旧报告。

### 4.3 创建成图任务

用户从商品工作台创建任务，并选择：

- 只生成主图套图；
- 只生成商品详情页；
- 同时生成两者。

任务固定引用一个竞品分析版本，并复制当时的模型路由和输出预设作为配置快照。选择两种输出时，两者共享研究结论和设计方向，但分别维护图片清单。

### 4.4 设计方案

系统根据商品资料和竞品报告生成 2–3 个候选设计方向。候选方向至少包含：

- 定位与视觉主题；
- 行业共性规律的使用方式；
- 差异化卖点；
- 配色与氛围；
- 版式意图；
- 文案策略；
- 主图和/或详情页图片清单初稿。

用户选择一个方向后，可以修改以上内容，并可对每份图片清单增删、编辑和拖动排序。图片项至少描述目标、卖点、建议文案、构图意图、参考素材和输出预设。

确认方案会产生不可变方案版本。后续如需更改方案，应创建新版本；已生成图片继续引用原方案版本。

### 4.5 批量生成与验收

确认方案后，系统为每个图片项创建独立后台任务。可以并行或排队执行，但状态、错误、重试和结果必须按图片项隔离。

图片模型以商品参考图、设计方向、图片项说明和输出尺寸为输入，直接输出扁平位图。用户主观验收每张结果，可以：

- 选定为当前版本；
- 重新生成一个创意版本；
- 对失败调用执行重试；
- 进入局部微调；
- 比较或恢复历史版本。

### 4.6 局部微调

用户在当前图片上用画笔或框选产生遮罩，并输入自然语言指令。后端把原图、遮罩、指令和当前图片编辑场景的模型配置发送给图片编辑模型。

成功结果创建新的不可变图片版本，并记录父版本、遮罩、指令、模型和参数。第一版不解析位图内的文字或元素，也不支持结构化移动、修改或删除。

### 4.7 导出

- 主图套图：按图片清单顺序导出 PNG/JPG，可单张下载或整套打包。
- 商品详情页：每个模块可单独下载，也可按当前顺序自动拼接成长图后导出。
- 导出使用任务保存的输出预设快照，不受设置页后续修改影响。

## 5. 页面与信息架构

### 5.1 全局导航

- 商品库：主要入口，浏览、搜索、创建和归档商品。
- 任务中心：集中显示运行中、失败、已中断和等待导出的任务。
- 设置：维护供应商、模型、场景路由和输出预设。

### 5.2 商品工作台

- 商品资料：商品参考图、规格参数和核心卖点。
- 竞品研究：竞品素材集、逐图卡片、人工修正和综合报告版本。
- 成图任务：该商品的任务历史和新建入口。

### 5.3 成图任务

任务采用四步流程：

1. 任务范围：选择输出类型、竞品分析版本和输出预设；
2. 设计方向：比较并选择候选方向；
3. 方案编辑：修改方案与图片清单；
4. 生成验收：观察进度、处理失败、微调、选定版本和导出。

每一步均持久化，用户刷新或关闭浏览器后可以继续。

## 6. 领域模型

### 6.1 商品聚合

`Product` 是长期根对象，包含：

- `ProductAsset`：自有商品参考图；
- `ProductSpecification`：结构化或自由文本规格；
- `SellingPoint`：核心卖点；
- `CompetitorAsset`：手动上传的竞品图片；
- `AnalysisVersion`：竞品分析版本；
- `GenerationTask`：成图任务。

删除商品默认采用归档，不立即删除物理图片。第一版只有在用户明确执行永久删除且不存在运行任务时，才允许清理相关资产。

### 6.2 竞品分析

`AnalysisVersion` 固定引用一组竞品资产版本，包含：

- 多个 `ImageAnalysisCard`；
- 每张卡片的 `model_output` 与可选 `human_override`；
- 一个 `SynthesisReport`；
- 证据图片引用；
- 模型调用与提示词快照。

综合报告读取“人工值优先，否则模型值”的有效卡片内容。

### 6.3 成图任务

`GenerationTask` 固定引用：

- 一个商品；
- 一个分析版本；
- 一个任务配置快照；
- 选中的输出类型集合；
- 多个 `DesignDirection`；
- 一个或多个 `DesignPlanVersion`。

一个方案版本分别持有可选的 `MainImageList` 和 `DetailModuleList`。两者均由有序 `ImageItem` 组成。

### 6.4 图片与版本

每个 `ImageItem` 有零个或多个 `ImageVersion`，并有一个可空的当前选定版本指针。

图片版本来源包括：

- 初始生成；
- 重新生成；
- 局部 AI 微调。

图片版本不可变。恢复旧版本只改变当前选定版本指针，不删除后来的版本。

## 7. 系统架构

### 7.1 总体结构

采用本地模块化单体：

- 浏览器前端负责交互、表单、状态展示、图片圈选和版本比较；
- 本地后端提供 HTTP API、业务校验、后台任务、文件处理和模型网关；
- SQLite 保存结构化数据；
- 本地文件目录保存原始素材、模型输入输出、遮罩与导出文件；
- 外部模型通过供应商适配器调用。

第一版不拆微服务，不依赖 Redis、云对象存储或外部数据库。

### 7.2 业务模块

- 商品与素材模块；
- 竞品研究模块；
- 设计方案模块；
- 成图与版本模块；
- 后台任务模块；
- 导出模块；
- 设置与模型网关模块。

模块通过领域接口协作，不直接修改其他模块的数据表或依赖供应商专有结构。

### 7.3 持久化

SQLite 保存元数据、内容、关系、状态、配置快照和调用日志。图片和二进制内容写入由后端管理的数据目录；文件名使用内部资产 ID，不信任上传文件名。

数据库与文件目录共同构成一个数据集，备份、恢复和迁移必须整体执行。删除文件前需检查数据库引用；写入新文件采用临时文件加原子重命名，避免产生半文件。

建议的本地数据分区：

- `assets/originals`：商品图和竞品原图；
- `assets/generated`：生成与微调版本；
- `assets/masks`：局部编辑遮罩；
- `exports`：临时导出结果；
- `database`：SQLite 数据库；
- `secrets`：后端专用供应商凭据。

这些运行数据不进入 Git。

## 8. 模型网关与设置

### 8.1 首批供应商

- 百炼；
- 火山方舟 / 豆包；
- GPT 中转服务。

GPT 中转配置允许填写后端访问的基础地址、API 密钥和模型标识。所有供应商凭据只由后端使用。

### 8.2 场景路由

第一版定义五个场景：

- `competitor_image_analysis`：单张竞品图片理解；
- `competitor_synthesis`：综合规律与差异化机会；
- `design_plan`：候选方向、文案和图片清单；
- `image_generation`：端到端整图生成；
- `image_edit`：遮罩局部编辑。

每个场景只绑定一个供应商模型。提交任务前校验模型是否声明所需能力。失败时不自动切换模型，用户可以重试或到设置页修改未来任务的路由。

任务保存路由、模型和参数快照。修改设置不改变已提交任务，也不改变旧结果的来源记录。

### 8.3 输出预设

设置页可维护主图和详情模块的默认预设，包括宽度、高度、格式和 JPG 质量。系统提供可编辑的初始预设：

- 主图：1000 × 1000，JPG，质量 90；
- 详情模块：宽 790、高 1000，JPG，质量 90。

这些值是首次运行的工作起点，不代表平台永久限制。创建任务时可以覆盖，任务保存覆盖后的快照。

### 8.4 凭据边界

- 本地服务只监听回环地址，并校验浏览器来源。
- 密钥由后端写入独立凭据文件，使用当前系统用户可读写的文件权限。
- API 不返回完整密钥；设置页只显示是否已配置和末尾脱敏字符。
- 密钥、完整供应商响应和含密钥的请求头不得写入日志。
- 第一版不防御已经取得当前操作系统用户权限的攻击者。

## 9. 后台任务与状态

分析、综合、方案生成、图片生成、图片编辑和导出统一使用持久化后台任务。

任务状态为：

- `queued`；
- `running`；
- `succeeded`；
- `failed`；
- `cancelled`；
- `interrupted`。

提交后台任务时，先在同一数据库事务中保存业务输入快照和排队记录，再由工作器领取。浏览器仅轮询或订阅状态，不持有执行生命期。

本地服务重启时：

- `queued` 任务可继续领取；
- 原 `running` 任务改为 `interrupted`，由用户手动重试；
- 已成功结果不重复激活。

“重试”沿用相同业务输入、模型和参数，处理执行失败；“重新生成”代表新的创意尝试并产生新的图片版本。两者在界面和审计记录中必须区分。

## 10. 错误处理

### 10.1 提交前错误

缺少模型、密钥、商品图片、分析版本或输出预设时阻止提交，并提供到对应修复位置的直达入口。

### 10.2 供应商错误

模型网关把供应商错误归一为认证失败、限流、超时、内容拒绝、能力不支持、无效响应和未知错误。界面显示可操作的简明原因，诊断详情保留在本地调用记录中。

系统不自动切换供应商或模型。

### 10.3 批量部分失败

批量生成的每个图片项独立执行。一张失败不取消其他图片。任务页面汇总成功、执行中和失败数量，并允许只重试失败项。

### 10.4 文件错误

读取资产前验证存在性和内容校验值。源文件缺失或损坏时阻止依赖它的新任务，不静默跳过或使用其他图片替代。

### 10.5 取消

取消是尽力而为。若供应商无法真正终止请求，后端把本地任务标记为已取消；迟到响应可以保留为诊断资产，但不得自动成为当前业务结果。

## 11. 追溯与观察数据

每个分析报告、方案版本和图片版本至少记录：

- 输入资产 ID 与内容校验值；
- 上游分析、方案或图片版本 ID；
- 模型场景、供应商、模型和参数；
- 最终提示词、用户编辑或微调指令；
- 开始、完成和持续时间；
- 结果状态与归一化错误；
- 用户最终是否选用该版本。

系统可以展示生成次数、微调次数和最终选用版本，帮助用户比较模型效果；这些数据不构成自动验收门槛。

## 12. 测试策略

### 12.1 领域测试

覆盖商品归属、分析版本、人工值优先规则、方案确认、双图片清单、不可变图片版本、配置快照和后台任务状态转换。

### 12.2 模型适配器契约测试

每个适配器使用固定请求与响应样本测试：

- 能力声明；
- 请求转换；
- 正常响应解析；
- 图片与遮罩传输；
- 错误归一化；
- 日志脱敏。

真实 API 只做显式触发的冒烟测试，常规测试不得产生外部费用。

### 12.3 存储与图片处理测试

覆盖上传校验、原子写入、引用保护、缺失文件、图片尺寸与格式转换、模块排序、详情长图拼接、数据库与文件整体恢复。

### 12.4 工作流集成测试

使用可控的假模型网关覆盖黄金路径：

商品建档 → 上传竞品图 → 逐图分析 → 人工修正 → 综合报告 → 创建主图与详情任务 → 选择并编辑方案 → 批量生成 → 单图失败重试 → 圈选微调 → 版本恢复 → 导出。

同时覆盖浏览器关闭、后端重启、部分失败、取消和迟到响应。

### 12.5 人工成图验收

模型输出不做像素级固定断言。人工检查商品与主题相关性、参数准确性、中文可读性、明显畸变或伪影、套图风格统一性，以及局部修改是否符合指令。

## 13. 第一版交付边界

第一版完成的标志是用户可以在本机浏览器中完成一条真实商品黄金路径，并能在服务重启后继续查看所有已持久化的商品、分析、任务、结果与版本。

成图质量是否可用由用户主观判断。若端到端模型对商品细节的修改超过实际可接受范围，应先通过更换模型、提示词和参考图改善；第一版不临时引入分层合成编辑器。
