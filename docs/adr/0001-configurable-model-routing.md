# ADR 0001：按工作流场景配置模型路由

- 状态：已接受
- 日期：2026-08-01

## 背景

系统包含竞品视觉分析、卖点与文案处理、设计方案生成、图片生成和局部图片编辑等不同能力。单一模型不一定在所有场景下同时满足质量、成本、速度和可用性要求。

首批需要支持的模型渠道为：

- 百炼；
- 火山方舟 / 豆包；
- GPT 中转服务。

## 决策

在业务工作流与外部模型之间设置统一的模型适配与路由层。路由键按工作流场景定义，而不是按整条任务定义；每个场景可以配置独立的供应商、模型和参数。

首批候选场景包括：

- 竞品图片理解；
- 行业规律与差异化机会总结；
- 设计方案与文案生成；
- 背景或场景图片生成；
- 局部图片编辑。

业务领域对象不得保存供应商专有的请求或响应结构。模型调用需保留场景、配置版本、调用状态和必要的可追溯元数据。

唯一用户通过系统的“设置”页面维护供应商凭据、模型清单和场景路由；业务任务页面不重复要求选择模型。

每个场景只绑定一个模型。模型调用失败时不得静默切换供应商或模型，系统应记录失败并允许用户重试。

## 影响

- 可以按场景独立调整效果、成本和速度。
- 可以替换供应商而不改动业务工作流。
- 需要统一不同供应商的能力描述、错误类型和调用日志。
- 失败行为可预测，但模型暂时不可用时需要用户处理配置或稍后重试。
