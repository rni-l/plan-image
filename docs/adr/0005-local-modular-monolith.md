# ADR 0005：本地模块化单体与混合持久化

- 状态：已接受
- 日期：2026-08-01

## 背景

系统是单用户、本机浏览器访问的网页系统，但包含多个长耗时 AI 任务、大量图片文件和可恢复的版本历史。

## 决策

采用一个本地模块化单体后端，为浏览器前端提供 HTTP API，并在同一应用中划分以下业务模块：

- 商品与素材；
- 竞品研究；
- 设计方案；
- 成图与版本；
- 后台任务；
- 导出；
- 模型网关与供应商适配器。

结构化数据使用 SQLite；原始上传图、模型输入输出、微调遮罩和导出文件保存在受控的本地文件目录。数据库保存资产路径、校验信息及业务关联。

耗时的分析、生成、微调和导出操作通过持久化后台任务执行，前端只负责提交命令和观察状态。

## 影响

- 部署和本地备份保持简单，无需微服务或外部数据库。
- 代码仍须保持模块边界，禁止业务模块直接依赖供应商专有协议。
- 数据库记录与图片文件必须作为一个整体备份和迁移。
- API 密钥只由本地后端读取，不返回前端，不写入调用日志；设置页仅显示脱敏状态。
